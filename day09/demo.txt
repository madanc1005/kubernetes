Node Affinity


Node Affinity tells Kubernetes to place the Pod on a node that has the required label, such as gpu=true.
Without this rule, Kubernetes may choose another suitable node that does not have the GPU your application needs.


Types of Node Affinity
Kubernetes has two main types.
1. requiredDuringSchedulingIgnoredDuringExecution
- The rule is mandatory when scheduling the Pod.
- If no node matches the rule, the Pod stays Pending.
- If the node's labels change later, Kubernetes does not automatically move the running Pod.
2. preferredDuringSchedulingIgnoredDuringExecution
- The rule is a preference, not a requirement.
- Kubernetes tries to choose a matching node.
- If no matching node is available, Kubernetes can choose another suitable node.


apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: disk
                operator: In
                values:
                  - ssd
  containers:
    - name: nginx
      image: nginx
